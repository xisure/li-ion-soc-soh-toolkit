## 1. 动手前：先问清这 8 件事

**下面每一项都直接决定一个配置值。缺哪一项就去问使用者，不要用默认值糊过去。**

| # | 要问的 | 影响 |
|---|---|---|
| 1 | MCU 型号 + 工具链（Keil / IAR / GCC / MounRiver…） | 时基怎么取、Flash 写接口怎么写、中文注释编码 |
| 2 | 主循环周期是多少 ms | `BMS_UPDATE_PERIOD_MS`（默认 200） |
| 3 | 电芯型号 / 标称容量 mAh | `SOC_CAPACITY_NOMINAL_MAH`（默认 3350） |
| 4 | 有没有 1 ms 递增、32 位自然回绕的计数器 | `BMS_USE_TICK`（有=1，没有=0） |
| 5 | **有没有该电芯的 OCV / R0 / R1 / τ 标定数据** | 没有就只能先跑通、后标定（见 §7） |
| 6 | 要不要掉电保持（学习结果存 Flash/EEPROM） | `BMS_USE_NVM` + 3 个槽函数 |
| 7 | 要不要串口在线调参 | `BMS_USE_TUNE` |
| 8 | 工程源码是 GBK 还是 UTF-8 | 本库源码是 UTF-8；GBK 工程接入前先转码（见 §6） |

> ⚠ 第 5 项最容易漏。**用错电芯的标定表比不标定更糟** —— 它会让 SOC 看起来
> "在工作"但系统性偏移。使用者的电芯不是 18650 / 3350 mAh 时，务必确认这一点。

## 2. 移植流程（按顺序做，每步有判据）

### 步骤 1 —— 把源文件加进工程

**必加（10 个文件）**：

```
bms_algo.h  bms_config.h  bms_port.h  bms_port.c
bms_cal.h   bms_cal.c     soc.h  soc.c  soh.h  soh.c
```

**按需加**：

| 文件 | 什么时候加 |
|---|---|
| `bms_nvm.h` / `bms_nvm.c` | 要掉电保持（`BMS_USE_NVM = 1`） |
| `bms_tune.h` / `bms_tune.c` | 要在线调参（`BMS_USE_TUNE = 1`） |

应用代码**只需要 `#include "bms_algo.h"`**（它会把其余头文件都带上）。

> ⚠ **`移植示例/` 目录不要整个加进工程** —— 多个文件实现同一个
> `BMS_Port_GetTickMs()` 会链接冲突。挑一个拷进你的源目录，或把内容抄进已有文件。

**判据 1**：工程能编译过，且 `bms_algo.h` 的 `#include` 链全部能解析（没有 "file not found"）。

---

### 步骤 2 —— 实现时基（唯一需要写的代码）

从 `移植示例/` 里挑一个最接近的：

| 你的平台 | 用哪个 | 内容 |
|---|---|---|
| STM32 + HAL | `port_stm32_hal.c` | `return HAL_GetTick();` |
| CH32X035（WCH） | `port_ch32x035.c` | 转发到软件定时器计数 |
| 裸机 / 其它 MCU | `port_bare_1ms_isr.c` | 自己开 1 ms 中断累加 |
| RTOS | 照抄上面任一个 | 时基接口只要求"1 ms 递增、32 位回绕"，RTOS 的 tick 直接满足 |

```c
/* 你唯一必须实现的函数 */
uint32_t BMS_Port_GetTickMs(void);
```

**如果确实没有毫秒时基**：把 `bms_config.h` 里 `BMS_USE_TICK` 改成 `0`，
算法内部按 `BMS_UPDATE_PERIOD_MS` 的标称周期自累加。
代价是**主循环周期必须真的准**（不能用"大概 200 ms"的延时）。

**判据 2**：写一个临时探针，连续调用 10 次，打印两个时间戳之间的差值 ——
必须等于真实等待的毫秒数（±5%）。**差了就是时基没接对，别往下走。**

---

### 步骤 3 —— 改配置（只改 `bms_config.h` 这一个文件）

`bms_config.h` 是**唯一的配置入口**，共 10 组。移植阶段真正必须动的是这两组：

| 组 | 改什么 |
|---|---|
| **[1] 电芯参数** | `SOC_CAPACITY_NOMINAL_MAH` + 四张表（OCV / R0 / R1 / τ） |
| **[2] 调度与时基** | `BMS_UPDATE_PERIOD_MS` 改成你的真实主循环周期 |

其余 8 组**保持默认即可**，需要时再按 §4 查。每组标题下都写了"什么时候需要改 / 改了会怎样"。

> ⚠ **别把配置值抄到别的文件里。** 全库只有 `bms_config.h` 一处定义；
> 在 `soc.c` / `soh.c` 里写第二份会让后续修改静默失效。
> 文件末尾有"编译期一致性自检"—— 整数类参数改冲突了会**直接编译报错**，这是有意的。

**判据 3**：`grep SOC_CAPACITY_NOMINAL_MAH` 全工程命中 1 处（`.h` 里）；
`.c` 文件里命中 0 处。

### 步骤 4 —— 写主循环

```c
#include "bms_algo.h"

int main(void)
{
    /* ... 你的外设初始化 ... */

    BMS_CAL_Init();                 /* 1. 刷出当前温度的活跃标定表 */
    SOH_Init();                     /* 2. 快照 R0 标定基线 + 清学习状态 */
    /* 若开了掉电保持: BMS_NVM_Init(); —— 必须在 SOH_Init() 之后 */

    while (1)
    {
        if (/* 距上次调用 >= BMS_UPDATE_PERIOD_MS */)
        {
            int32_t v_mv, i_ma, t_dc;

            if (sample(&v_mv, &i_ma, &t_dc))    /* 你的采样函数 */
            {
                BMS_CAL_Update(t_dc);           /* 温度变了就刷新表 */
                SOC_AhUpdate(v_mv, i_ma);       /* 先 SOC */
                SOH_Update(v_mv, i_ma, t_dc);   /* 后 SOH */
            }
            /* 采样失败（传感器掉线）的帧直接跳过，SOC/SOH 保持上次值 */
        }

        /* 若开了掉电保持: BMS_NVM_Task(); 放低频分支，不要进中断 */
    }
}
```

三个函数的入参单位（**弄错会让 SOC 直接算飞**）：

| 入参 | 单位 | 符号约定 |
|---|---|---|
| `v_mv` | 毫伏 | 电池端压（**不是**母线电压，要扣掉保护 MOS / 采样电阻压降） |
| `i_ma` | 毫安 | **放电为正、充电为负** |
| `t_dc` | 0.1 °C | 250 = 25.0 °C |

**判据 4**：跑 30 秒，每帧打印 `SOC_GetPercent01()` ——
必须是一个**合理且有变化**的值（静置时稳定、带载时缓慢单调变化）。
恒为 0 或恒为 10000 都说明入参单位或符号错了。

**判据 5**：

- `-Wall -Wextra` 下 **0 error 0 warning**；
- 链接后 Flash 增量 ≈ **12.6 KB**、RAM 增量 ≈ **375 B**（仅核心）。
  超出 2 倍以上说明你误加了可选模块，或有别的东西被链进来了。

### 步骤 6 —— 验收（不做这一步等于没移植完）

| # | 做法 | 通过判据 |
|---|---|---|
| 1 | 上电后静止放置 | SOC 落在按端压查 OCV 表应有的位置（±5%） |
| 2 | 连续放电 10 分钟 | SOC **单调下降**，不跳变、不反向 |
| 3 | 断开负载静置 ≥ `SOC_IDLE_MS`（默认 900 s） | SOC 被 OCV 拉回一档，且**单次修正量** ≤ `SOC_RESYNC_MAX_01` |
| 4 | 看 SOH 初始值 | `SOH_GetPercent()` = **100**（还没学到东西，正常） |
| 5 | 做几次深充深放后 | `SOH_IsCapacityValid()` 变 1；`SOH_GetLearnedCapacityMAh()` 落在合理区间 |
| 6 | 传感器拔掉一帧再插回 | SOC/SOH 不跳变（掉线帧被正确跳过） |

> 第 4 条是**最容易被误判成 bug 的现象**：SOH 刚上电恒为 100%，
> 因为"还没学到过容量与内阻"。这不是故障，见 §5。

### 步骤 7（可选）—— 掉电保持

打开 `BMS_USE_NVM = 1`，然后实现 3 个槽函数（从 `移植示例/port_nvm_*.c` 挑一个）：

```c
uint8_t  BMS_NVM_SlotCount(void);                       /* 有几个独立擦除单元 (>=1) */
uint8_t  BMS_NVM_SlotRead (uint8_t slot, void *buf, uint32_t len);
uint8_t  BMS_NVM_SlotWrite(uint8_t slot, const void *buf, uint32_t len);
```

**「槽 = 一个独立擦除单元」**（Flash 页 / 扇区，或 EEPROM 里的一段）。
**同一擦除单元不能拆成两个槽**，否则擦一个会连带毁掉另一个。

落盘格式是固定 **132 字节**（12 B 头 + 120 B 载荷），多槽轮转做磨损均衡。
细节见 `算法库/README.md` §7。

**判据 7**：写入后断电重启，`SOH_GetLearnedCapacityMAh()` 与断电前一致。

---

### 步骤 8（可选）—— 在线调参

打开 `BMS_USE_TUNE = 1`，接两个**逐字节**的钩子：

```c
BMS_TUNE_SetTx(你的发送函数);   /* 上电注册一次：应答帧的每个字节都从这里出去 */
BMS_TUNE_Feed(byte);            /* 串口每收到一个字节，就喂一个 */
```

| 方向 | 声明 | 说明 |
|---|---|---|
| 收 | `void BMS_TUNE_Feed(uint8_t b);` | 每字节调一次 —— **没有"喂一整帧"的接口** |
| 发 | `typedef void (*bms_tune_tx_fn)(uint8_t b);` | 每字节调一次 —— 直接写发送寄存器，或塞进发送环形缓冲 |

> ⚠ **`BMS_TUNE_Feed()` 不要在中断里调** —— 主循环的 `SOC_AhUpdate()` 正在读标定表，
> 中断里改表会读到半更新的状态。正确做法：中断里只把字节塞进环形缓冲，
> 主循环里 `while (环形缓冲非空) { BMS_TUNE_Feed(取一个字节); }`。

> ⚠ **本模块不做任何鉴权。** 谁能喂字节，谁就能改标定表、改容量、**强制改 SOC**。
> 量产固件建议保持关闭，只在标定工装 / 开发版本打开。

**判据 8**：往 `BMS_TUNE_Feed()` 依次喂下面这 10 个字节（PING），
应当收到 10 字节应答，且 `payload[0] == 0`（rc=OK）、`payload[1..2] == 02 00`（proto_ver=2）：

```
AA 55 03 00 80 00 02 00 AA 7B
```

帧格式与 34 条命令的逐字节布局见 `算法库/在线调参协议.md`（**权威规范**），
接线与验收见 `算法库/移植与对齐指南.md`。

## 3. 三条不能弄反的硬性约定

**弄反不会报错，只会静默算错** —— 这是本库移植时最常见的坑。

1. **初始化顺序**：`BMS_CAL_Init()` → `SOH_Init()` → `BMS_NVM_Init()`
   `SOH_Init()` 要把标定 R0 表快照成 SOH 的分母，早于 `BMS_CAL_Init()` 会取到空表。
   （典型症状：SOH 恒等于 100%。）

2. **每帧调用顺序**：`BMS_CAL_Update()` 必须在 `SOC_AhUpdate()` 之前
   否则这一帧用的还是旧温度的活跃表。

3. **掉线帧必须跳过**：V/I 无效时不要调 `SOC_AhUpdate()` / `SOH_Update()`
   守卫放在你自己的采样结果判断上，**不要指望库内部兜底**。

## 4. 配置速查（改什么 → 改哪个宏）

| 想改什么 | 改哪个宏 | 组 |
|---|---|---|
| 换电芯 / 换标称容量 | `SOC_CAPACITY_NOMINAL_MAH` + 4 张表 | [1] |

## 5. 症状 → 原因对照表

| 症状 | 最可能的原因 |
|---|---|
| **SOH 恒等于 100%** | ① 正常 —— 还没学到东西，看 `SOH_IsCapacityValid()`；② `SOH_Init()` 早于 `BMS_CAL_Init()`（顺序错） |
| SOC 恒为 0 或恒为 100% | 入参单位 / 符号错：`v_mv` 传成 V、`i_ma` 放电传成负 |
| SOC 带载时反向跳 | 电流符号反了（本库约定**放电为正**） |
| SOC 长期偏高、静置拉不回来 | 静置判据没满足：电流没真正小于 `SOC_IDLE_CUR_MA`，或静置时长不够 |
| SOC 在静置时抖动 | 静置电流门限设太大，把噪声当成了电流；或 `SOC_QUIET_DEBOUNCE` 太小 |
| 容量学习永远触发不了 | `SOH_MIN_REST_MS` / `SOH_Q_MIN_DSOC_01` / `SOH_Q_MIN_DQ_MAH` 对你的工况太严（短循环、浅充浅放学不到容量是**判据本身的性质**，不是 bug） |
| R0 表不更新 | 样本温度超出 `SOH_TEMP_LO_C`~`SOH_TEMP_HI_C`（默认 15~35 °C）窗口 |
| SOH 缓慢往上跳 | `SOH_Q_KF_RUP` / `SOH_Q_KF_Q` 融合太猛 |
| 低温 / 大倍率下 SOC 偏高 | 温度 / 倍率修正**默认是关的**（占位值），要标定 `SOC_CAP_TEMP_PCT` / `SOC_PEUKERT_K` |
| 上电后学习结果丢了 | 没开 `BMS_USE_NVM`，或 `BMS_NVM_Init()` 放在了 `SOH_Init()` 之前 |
| 掉电保持写不进 | 链接脚本没把槽所在页/扇区让出来；或两个槽落在同一个擦除单元 |
| 主循环被拖慢 | `BMS_NVM_Task()` 被放进了中断或高频路径（Flash 擦写是阻塞的） |
| 编译报 `#error` | `bms_config.h` 末尾的编译期自检拦下了参数冲突 —— **照提示改**，不要注释掉检查 |

完整的移植期踩坑清单见 `算法库/README.md` §7.6 与 `算法库/移植与对齐指南.md` §7。

## 6. 文件与编码

| 内容 | 编码 | 换行 |
|---|---|---|
| 源文件 `.c` / `.h` | UTF-8 | LF，无 BOM |
| 文档 `.md` | UTF-8 | LF |

**如果你的工程是 GBK**（Keil / MounRiver 中文工程默认）：先把本库源码转码再入工程 ——

```bash
iconv -f UTF-8 -t GBK soc.c > soc_gbk.c    # 逐个文件，或写个循环
```

转码后功能完全不受影响（改动只在注释里），但**别只转一部分**，
混着编码的工程在部分 IDE 里会显示乱码。

**转成 GBK 后改中文注释时注意**：GBK 表示不了的字符（emoji、`⚠` 等）会被 IDE 静默替换成 `?`。

## 7. 没有标定数据怎么办

**先跑通，后标定。** 随附的四张表只有 25 °C 是实测的，且基于 18650 / 3350 mAh 电芯。

顺序建议：

1. **先用默认表把链路跑通**（§2 步骤 1-6），确认 SOC 会动、会跟负载走；
2. **再用自己的电芯重标四张表** —— 这是精度的天花板，滤波只能把数字做稳、不能做准；
3. 换完 `SOC_TAU_TABLE_S` 记得回头核对 `[3]` 的两个静置时长：
   经验关系是 `静置时长 ≈ 5~8 倍 τ_max`。τ 变大而静置时长没跟上，
   OCV 读数会**带极化**，把 SOC 基准和容量学习**系统性**带歪。

标定方法（HPPC 脉冲法 + 十档放电拟合法）见 `脚本/README.md`。
这一步需要程控电源或电子负载，**没有硬件就先用默认表，别硬凑数字**。

## 9. 明确不要做的事

- **不要改库源码去"适配"你的工程** —— 所有适配点都收在 `bms_config.h`
  和 `BMS_Port_GetTickMs()` 里。改了库源码，下次更新就冲突。
- **不要在 `.c` 里写第二份配置值**。
- **不要把 `BMS_NVM_Task()` 放进中断**。
- **不要跳过判据** —— 尤其步骤 2 的时基探针和步骤 6 的验收。
  这两处跳过的话，后面所有现象都无法解释。
- **不要在没确认电芯一致的情况下声称"移植完成"** ——
  用错电芯的标定表比不标定更糟。
