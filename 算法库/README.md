# 锂电池 SOC / SOH 估计算法库

> 本目录 = 仓库根的 `算法库/`；配套 PC 标定工具链在 `../脚本/`。
> 源码编码 **UTF-8**、换行 **LF**、无 BOM，与 GitHub / VS Code / 现代 IDE 的默认一致。
> 工程若是 Keil / MounRiver 的 GBK 默认编码，接入前先转码
> （`iconv -f UTF-8 -t GBK`，改动只在注释里），不要只转一部分。

面向单片机的锂电池 **SOC（荷电状态）+ SOH（健康度）** 在线估计算法库。
纯 C99，不依赖任何平台、RTOS、动态内存与文件系统。

## 1. 这是什么

### 特性

- **混合 SOC 估计** —— 带载走安时积分，静置满 `SOC_IDLE_MS` 后由 OCV 查表重同步基准，
  全程并行一阶 RC 扩展卡尔曼滤波（EKF）做端压平滑与极化电压观测
- **SOH 在线学习** —— R0 从电流阶跃 `ΔV/ΔI` 学，容量 Q 从静置 OCV 锚点学，
  Q 用标量卡尔曼融合，学习结果掉电可保持
- **多温度标定表** —— 5 / 25 / 45 °C 三点各一套，按当前温度插值出活跃表；
  **老化量与温度量解耦**，温度刷新不会抹掉学到的东西
- **工况修正** —— 可用容量按温度（`Q(T)` 表插值）与倍率（Peukert）折算；
  **默认参数下两个系数恒为 1，逐位等价于未引入**（见 §6）
- **双向内阻学习** —— 充电 / 放电各一张 R0 表，样本数各自收敛，
  充电方向不再因为"电流为负进不了带载段"而学不到
- **生命周期计数** —— 半循环（摆幅法）与等效满循环两个互补口径 + 累计充放电量，
  与学习结果共用同一份载荷落盘
- **掉电保持**（可选）—— 平台无关的 132 字节落盘格式，多槽轮转磨损均衡
- **在线调参**（可选）—— 通道无关的二进制协议，运行时改标定表与参数，
  同一套协议可挂 UART / USB CDC / CAN / 蓝牙
- **移植成本极低** —— 默认只需实现 1 个函数：`BMS_Port_GetTickMs()`

### 规格

| 项 | 值 |
|---|---|
| 语言 / 标准 | C99，`<stdint.h>` 必需；`expf()` 可用开关去掉 |
| 文件数 | 14 个源文件（核心 8 + 多温度标定 2 + 掉电保持 2 + 在线调参 2） |
| Flash | **12.6 KB**（仅核心）/ 14.8 KB（+掉电保持）/ 19.4 KB（+在线调参） |
| RAM | **375 B**（仅核心）/ 641 B（+掉电保持）/ 932 B（+在线调参） |
| 需要平台提供 | 1 个函数（开掉电保持再加 3 个槽函数） |
| 浮点 | 统一 `float`；无 FPU 平台可软件浮点，或改用库内泰勒近似 |
| 栈 | 无递归、无大局部数组，单一函数最大栈帧 < 64 B |

### 算法一句话概括

```
带载  -> 安时积分 SOC = 基准 - Σ(I·Δt)/容量
静置  -> |I|<20mA 满 900s 时用 OCV 查表值平滑校正基准（首次直接覆盖）
全程  -> 一阶 RC EKF 同时跑，做端压平滑 + 极化电压观测 + SOC 微修正
SOH   -> R0 从电流阶跃 ΔV/ΔI 学、容量 Q 从静置 OCV 锚点学（标量卡尔曼融合）
```

数据流**单向无环**：

```
你的采样代码 --原始量(V/I/T)--> soc.c / soh.c --估计结果--> 显示 / 上报
```

## 3. 快速开始

### 第 1 步：把源文件加进工程

拷贝这 10 个文件并加入编译：

```
bms_algo.h  bms_config.h  bms_port.h  bms_port.c
bms_cal.h   bms_cal.c     soc.h  soc.c  soh.h  soh.c
```

不用掉电保持就不加 `bms_nvm.*`，不用在线调参就不加 `bms_tune.*`。

### 第 2 步：实现时基（唯一需要写的代码）

从 `移植示例/` 挑一个：

| 平台 | 用哪个 | 内容 |
|---|---|---|
| STM32 + HAL | `port_stm32_hal.c` | `return HAL_GetTick();` |
| CH32X035 | `port_ch32x035.c` | 转发到你的毫秒计数器 |
| 裸机 / 其它 MCU | `port_bare_1ms_isr.c` | 自己开 1 ms 中断累加 |

> 表里没有的平台照做即可 —— 时基接口的全部要求就是"一个 **1 ms 递增、32 位自然回绕**
> 的计数器"。任何 RTOS 的 tick、任何定时器的毫秒计数都直接满足。

**嫌麻烦**：把 `bms_config.h` 里的 `BMS_USE_TICK` 改成 `0`，就完全不需要时基了 ——
算法内部按 `BMS_UPDATE_PERIOD_MS` 的标称周期自累加。代价是主循环周期必须真的准。

### 第 3 步：写主循环

```c
#include "bms_algo.h"

int main(void)
{
    /* ... 外设初始化 ... */

    BMS_CAL_Init();                 /* 用中间温度点刷出活跃表 */
    SOH_Init();                     /* 快照 R0 基线 + 清学习状态 */
    /* 若开了掉电保持: BMS_NVM_Init(); 必须放在 SOH_Init() 之后 */

    while (1)
    {
        if (/* 距上次调用 >= BMS_UPDATE_PERIOD_MS */)
        {
            int32_t v_mv, i_ma, t_dc;

            if (sample(&v_mv, &i_ma, &t_dc))        /* 你的采样函数 */
            {
                BMS_CAL_Update(t_dc);               /* 温度变了就刷新表 */
                SOC_AhUpdate(v_mv, i_ma);           /* 先 SOC */
                SOH_Update(v_mv, i_ma, t_dc);       /* 后 SOH */
            }
            /* 采样失败（传感器掉线）的帧直接跳过，SOC/SOH 保持上次值 */
        }

        /* 若开了掉电保持: BMS_NVM_Task(); 放主循环低频分支，不要进中断 */
    }
}
```

**三条硬性约定**：

1. `BMS_CAL_Init()` → `SOH_Init()` → `BMS_NVM_Init()`，顺序不能乱。
   `SOH_Init()` 要把标定 R0 表快照成 SOH 的分母，早于 `BMS_CAL_Init()` 会取到空表。
2. `BMS_CAL_Update()` 必须在 `SOC_AhUpdate()` 之前 —— 否则这一帧用的还是旧温度的活跃表。
3. **掉线帧不要调用 `SOC_AhUpdate` / `SOH_Update`** —— 传进来的 V/I 无效时，
   积分和状态机会被带跑。守卫放在你自己的采样结果判断上。

### 第 4 步：读结果

| 函数 | 返回 |
|---|---|
| `SOC_GetPercent()` | SOC，整数 %（0~100） |
| `SOC_GetPercent01()` | SOC，0.01% 单位（0~10000） |
| `SOH_GetPercent()` / `SOH_GetPercent01()` | 综合 SOH（取容量与内阻中较劣者） |
| `SOH_GetCapacityPercent()` | 只看容量维度的 SOH |

### 4.2 换电芯 → 只改 `[1] 电芯参数`

| 参数 | 说明 |
|---|---|
| `SOC_CAPACITY_NOMINAL_MAH` | 标称容量 mAh（上电初值 / 学习兜底值 / SOH 分母） |
| `SOC_CAP_LO_PCT` / `SOC_CAP_HI_PCT` | 运行期容量可用范围（默认 50%~110% 标称） |
| `SOC_OCV_TABLE_MV` | OCV-SOC 表（0%~100%，每 10% 一点） |
| `SOC_R0_TABLE_MOHM` | 欧姆内阻 vs SOC |
| `SOC_R1_TABLE_MOHM` | 极化电阻 vs SOC |
| `SOC_TAU_TABLE_S` | 极化时间常数 vs SOC |

**这四张表是精度的天花板** —— 滤波只能把数字做稳，不能做准。换电芯不重标表，
SOC 只能保证"不漂"，不能保证"准"。重标方法见 `脚本/README.md`（`soc_bench.py stair`）。

> 换完 `SOC_TAU_TABLE_S` 记得回头核对 `[3]` 的两个静置时长：
> 经验关系是 `静置时长 ≈ 5~8 倍 τ_max`（900s/125s = 7.2、600s/125s = 4.8）。
> τ 变大而静置时长没跟上，OCV 读数会带极化，把 SOC 基准 / 容量**系统性**学歪。

库内随附的表是针对示例电芯（1S 18650，3350 mAh）实测标定的，**换电芯必须重标**。

### 4.3 换平台 → 改 `[2] 调度与时基` 和 `[7] 移植开关`

| 参数 / 开关 | 什么时候改 |
|---|---|
| `BMS_UPDATE_PERIOD_MS` | 主循环不是 200ms 时改成你的周期（EKF 步长自动跟随） |
| `BMS_DT_MAX_MS` | 换成慢速平台 / 有长阻塞时放大 |
| `BMS_USE_TICK` | 不想实现时基函数时设 `0`（内部按标称周期自累加） |
| `BMS_USE_LIBM_EXPF` | 不想链 libm / 想省 expf 开销时设 `0`（用库内 6 阶泰勒近似） |

> 改 `BMS_UPDATE_PERIOD_MS` 时，三个"按帧数"定义的参数要一起换算：
> `SOC_QUIET_DEBOUNCE` / `SOH_IDLE_DEBOUNCE` / `SOH_R0_TAIL_N` ≈ `1000 / 周期`。

### 4.4 改坏了会直接编译报错

`bms_config.h` 末尾有**编译期一致性自检**，整数类参数冲突（滞回反了、上下限颠倒、
消抖 0 帧、网格越界……）一律 `#error` 拦下，不会带病上机。

**浮点参数没有编译期自检**（C 预处理器不认浮点常量），合法区间写在各自注释里。
需要记住的三条：

- `SOH_R0_LIMIT_RATIO` / `SOH_R0_ALPHA` / `SOH_Q_KF_P0` 都必须落在 `(0, 1]`
- `SOH_R_EOL_RATIO` 必须 `> 1`
- `BMS_EKF_Q_SOC` / `Q_VRC` / `R_V` / `P0_*` / `RES_MAX_MV` 必须 `> 0`

### 4.5 `[5] SOH 判据` 与 PC 工具链必须同步

`[5]` 这一组常量与 `脚本/soh_learn.py` 顶部的常量**一一对应，改一处必须改两处**
（`soh_mcu_sim.py` 启动时会逐项比对并报警）。

## 5. 多温度标定表

OCV / R0 / R1 / τ 全都随温度变。低温内阻成倍抬高、OCV 曲线整体下移；拿 25 °C
的表去算 5 °C 的电池，端压预测会系统性偏高一两百毫伏，EKF 新息长期为负，
SOC 被一路拖偏。

`bms_cal` 把"一张表"升级成"三个温度点各一张"，运行时按当前温度**线性插值**
出一张活跃表给算法用。

| 项 | 取值 |
|---|---|
| 温度点 | **5 / 25 / 45 °C**（单位 0.1 °C，即 50 / 250 / 450） |
| 温度点个数 | `BMS_CAL_TEMP_N` = 3（**代码没写死 3，改点数只需同步改表和此宏**） |
| 每张表点数 | `BMS_CAL_NSOC` = 11（SOC = idx × 10%，0~100%） |
| 表 | OCV(mV) / R0(mΩ) / R1(mΩ) / τ(s) 共 4 张 |
| 插值 | 相邻两点线性，**端点平延不外推** |
| 温度滞回 | 2 °C（`BMS_CAL_TEMP_HYST_DC`，温度读数噪声约 ±0.3 °C 触发不了） |

**为什么不外推**：三个点撑不起二次拟合，5 °C 以下 / 45 °C 以上没有数据，
外推出来的数没有物理依据，宁可用最近的标定点平延。要覆盖更宽温区，
正确的做法是**加温度点**。

### 5.1 默认只有 25 °C 是实测数据

库内随附的 5 °C / 45 °C 直接复用 25 °C 的值占位：

```c
#define SOC_OCV_25C_MV  3050, 3228, 3415, ...   /* 25 C 实测 */

#define SOC_OCV_TABLE_MV                            \
{                                                   \
    { SOC_OCV_25C_MV },   /*  5 C 待标定 (占位) */    \
    { SOC_OCV_25C_MV },   /* 25 C 实测 */            \
    { SOC_OCV_25C_MV }    /* 45 C 待标定 (占位) */    \
}
```

三个点相同 ⇒ 线性插值恒等于 25 °C 的值 ⇒ **不补数据时等价于"不随温度变"`**。

### 5.2 拿到实测数据后怎么填

**办法 A（改固件）** —— 在 `bms_config.h` 里把占位换掉，R0 / R1 / τ 同构：

```c
#define SOC_OCV_5C_MV   2970, 3150, 3340, ...   /*  5 C 实测 */
#define SOC_OCV_25C_MV  3050, 3228, 3415, ...   /* 25 C 实测 */
#define SOC_OCV_45C_MV  3090, 3260, 3440, ...   /* 45 C 实测 */

#define SOC_OCV_TABLE_MV   { { SOC_OCV_5C_MV }, { SOC_OCV_25C_MV }, { SOC_OCV_45C_MV } }
```

**办法 B（运行时写）** —— 用 `BMS_CAL_SetPoint()`，在线调参就走这条路。

标定方法：满充（4.20 V CV 到 C/20）后，在目标温度下 0.2 C 慢放到截止 2.8 V，
用库仑计数标 SOC = 100% − Q/Q_total，取 11 个 SOC 点的静置电压就是 OCV 表；
R0 / R1 / τ 用 HPPC 脉冲拟合（`脚本/soc_bench.py` 已支持）。三个温度各做一遍。

### 5.3 关键设计：老化量和温度量必须解耦

`bms_cal` 只提供**出厂基准**随温度怎么变；SOH 在线学到的老化量由 `soc.c` 用
**增量（delta）** 单独保存：

```
活跃 R0(idx) = BMS_CAL_GetBase(BMS_CAL_R0, idx)   /* 当前温度的出厂基准 */
             + s_r0_delta[idx]                    /* SOH 学到的老化增量 */
```

温度变了只换基准，delta 不动，学习成果自动跟着温度走。
**反过来若让 SOH 直接改写"表"**，每次温度刷新都会把学到的东西抹回出厂值。

落盘时同样靠这个拆分保证一致性：`soh_param_t` 存了落盘时的温度 `temp_dc`，
上电导入时**先切回落盘温度再导入 R0**（这一步由 `bms_nvm.c` 保证） ——
否则老化增量里会混进"落盘温度到当前温度"的基准差（低温下能差十几 mΩ）。

### 5.4 接口

| 函数 | 用途 |
|---|---|
| `BMS_CAL_Init()` | 上电初始化，用中间温度点刷一次活跃表 |
| `BMS_CAL_Update(temp_dc)` | 每帧调用；温度变化 ≥ 2 °C 才重算（内部滞回） |
| `BMS_CAL_SetTempDc(temp_dc)` | 强制切到指定温度（无视滞回），给上电导入用 |
| `BMS_CAL_GetTempDc()` | 当前活跃表对应的温度 |
| `BMS_CAL_GetBase(tbl, idx)` | 算法取基准值（不含老化量） |
| `BMS_CAL_GetPoint(ti, tbl, idx)` | 读某个温度点的标定点 |
| `BMS_CAL_SetPoint(ti, tbl, idx, v)` | **写**标定点，立刻生效并置脏标记 |
| `BMS_CAL_LoadDefault()` | 全部恢复成 `bms_config.h` 的出厂值 |
| `BMS_CAL_GetTempAt(ti)` | 读第 ti 个温度点的温度值 |
| `BMS_CAL_Serialize(buf, cap)` | 全部标定点 → 264 字节小端流 |
| `BMS_CAL_Deserialize(buf, len)` | 264 字节小端流 → 全部标定点 |

整表布局是 `[温度点][表][SOC点]` 每点 2 字节小端，共 `3×4×11×2 = 264` 字节：

```python
vals = struct.unpack('<264H', buf)
v = vals[ti * 44 + tbl * 11 + idx]      # 第 ti 个温度点 / 第 tbl 张表 / 第 idx 个点
```

越界调用一律静默返回（非法参数写不进、读出来是 0），下发的脏数据打不死固件。

### 5.5 精度与开销

| 项 | 值 |
|---|---|
| 插值权重 | Q8 定点（0~256），不用浮点 —— 无 FPU 平台每刷新一次省 44 次浮点乘加 |
| 插值误差 | R0 < 0.02 mΩ，OCV < 0.4 mV（1/256 步长） |
| 刷新一次耗时 | 44 次 `lerp`，每次约 6 条整数指令，48 MHz 下 < 20 µs；有滞回，实际几分钟才跑一次 |
| 代价 | RAM 356 B（基准副本 264 + 活跃表 88 + 标志 4）；Flash +2160 B（含自带级数近似，不链 libm） |

## 6. 工况修正、双向内阻学习与生命周期计数

前面几节讲"参数怎么配"，这一节讲**算法层的三块能力**。它们有一个共同前提：

> **默认参数下与引入之前逐位等价。** 标定之后才开始起作用。

```
可用容量 Q_eff = Q_run × f_T(T) × f_I(I)      <- 温度修正 x 倍率修正
R0 表          = 放电方向表 / 充电方向表        <- 双向分别学, 样本数各自收敛
寿命计数       = 半循环数 + 累计充放电量        <- 与学习结果同一份载荷落盘
```

### 6.1 为什么需要工况修正

`SOC = 基准 − Σ(I·Δt) / 可用容量`。问题在分母：**可用容量不是常数**。

| 工况 | 可用容量 | 不修正的后果 |
|---|---|---|
| 5 °C 放电 | 约 25 °C 的 93% | 同样的电荷被当成"更少的 SOC 消耗" → **SOC 偏高** |
| 0 °C 放电 | 约 25 °C 的 90% | 同上，偏差翻倍 |
| 2C 放电 | 比 0.2C 少 5% 以上 | 同上；且放电末端"跳崖"，SOC 还有 10% 电压就到截止 |
| 10 °C + 2C | 两者叠加，可差 10% 以上 | 显示 20%，实际已接近截止 |

修正做的事情就一句话：**把当前工况下的电荷，折算成参考工况下的等效电荷**。
折算之后 Ah 积分、OCV 重同步、EKF 三个基准同刻度，才不会互相打架。

### 6.2 两个系数

| 系数 | 公式 | 宏 | 默认值 |
|---|---|---|---|
| 温度 | `f_T = PCT[T] / 100`，在 `BMS_CAL_TEMP_DC` 温度点上线性插值 | `SOC_CAP_TEMP_PCT` | `{100, 100, 100}` → `f_T ≡ 1` |
| 倍率 | `f_I = (\|I\| / I_ref)^(1−k)`，`\|I\| < SOC_RATE_MIN_CUR_MA` 时取 1 | `SOC_PEUKERT_K` | `1.00f` → `f_I ≡ 1` |

- `I_ref = BMS_REF_CUR_MA`（默认 670 mA ≈ 0.2C）。
- `(\|I\| / I_ref)` 被钳在 `SOC_RATE_RATIO_LO .. HI`（0.25~4.00），
  把 `ln()` 的级数近似限制在收敛快的区间。
- 总系数 `K = f_T × f_I` 再钳一次 `SOC_CORR_MIN .. SOC_CORR_MAX`（0.5~1.5），
  挡温度 / 电流读数异常造成的离谱折算。
- `SOC_RATE_MIN_CUR_MA`（默认 150 mA）以下按参考倍率算：静置与漏电流不产生
  倍率效应，而且 `(I/I_ref)^(1−k)` 在小电流区会让系数乱跳。
- 级数近似在 `bms_cal.c` 里自带（`cal_expneg` / `cal_powf` / `cal_logf`），
  **默认不链 libm**，保证标定结果跨平台逐位一致。

### 6.3 折算落在哪 —— 只动分母，不动分子

容易搞错的地方：修正该作用在"容量"上还是"电流"上？

实数是等价的，**定点上不等价**。库里的做法是**把折算做进电流**：先把 `I` 折成
参考工况下的等效电流 `I/K`，再按 Q16 落成等效电量 —— 累加器保持严格线性：

```c
/* soc.c —— 唯一一处积分累加 */
s_coul_eq_q16 += (int64_t)cur_ma * dt_ms * SOC_Q16 * SOC_Q16
               / (int64_t)s_corr_q16;
```

读的时候只除一个**恒定**分母（`SOC_COUL_EQ_DIV × 360 × 容量`）。

> ⚠ **两个 `SOC_Q16` 都不能少。** `K` 本身是 Q16（`s_corr_q16 = K × 65536`），
> 所以 `65536 / K = 65536² / s_corr_q16`。只写一个的话累加器退化成 `ΣI·dt`，
> 而读取端仍按 Q16 除 —— 结果被压掉 65536 倍，表现为**库仑电量恒为 0、SOC 不动**。
> 这个坑本项目真踩过，`SOC_GetCoulombMAh()` 的非零断言就钉在这里。
>
> 若改成"每帧用当前可用容量折算"，不足 1 LSB 的部分会被整数除法逐帧截掉，
> 长时间小电流放电会积分成 0 —— 这是**有意选择"折算电流不折算容量"的原因**。

改这类代码时，任何"看起来只是换个写法"的代数变形，都要先用 `sim_learn.py`
第 [3] 节（等效电量对拍）过一遍：**定点上代数等价 ≠ 位模式等价**。

### 6.4 充电方向 R0 学习

原先只有一个 R0 表，且 `SOH_I_ON_MA = 500` 是"放电为正"方向的上门限。结果是
**充电方向的 R0 从来学不到** —— 充电电流为负，永远进不了带载段。

现在拆成两张表：

| | 放电方向 | 充电方向 |
|---|---|---|
| 进入带载段 | `I > +SOH_I_ON_MA` | `I < −SOH_I_ON_MA` |
| 读取 / 写入 | `SOC_GetR0At(idx)` / `SOC_SetR0At` | `SOC_GetR0ChgAt(idx)` / `SOC_SetR0ChgAt` |
| 通用形式 | `SOC_GetR0DirAt(0, idx)` | `SOC_GetR0DirAt(1, idx)` |
| 样本数 | `cnt[11]` | `cnt_chg[11]`（各自独立） |
| 方向 SOH_R | `SOH_GetResistancePercent()` | `SOH_GetResistancePercentChg()` |
| 方向网格均值 | `SOH_GetR0AvgMOhm()` | `SOH_GetR0ChgAvgMOhm()` |

关键设计：

- **方向在进入带载段时按电流符号定一次**（`s_r0_dir`），整段沿用。段内电流抖动
  不会让同一次测量同时写进两张表。
- **样本数按方向各自计**，所以自适应遗忘因子 `a_eff = max(ALPHA, 1/(cnt + N0))`
  与限幅门限 `R0_MIN_SAMPLE` 也各自独立收敛 —— 充电表刚建时不会被放电表的
  老样本数"带快"。
- **`SOH_IsR0Valid()` 与 `SOH_IsR0ChgValid()` 分开**，而 `SOH_R` 的门槛只看放电
  方向：充电方向的样本数往往少得多，拿它当综合 SOH_R 的门槛会让 SOH 长期不可用。

### 6.5 循环次数 —— 两个互补口径

| 口径 | 定义 | 宏 | 接口 | 用途 |
|---|---|---|---|---|
| **半循环（摆幅法）** | SOC 自极值回升（或自极值回落）超过 30% 记半个 | `SOH_CYCLE_SWING_01` | `SOH_GetHalfCycleCount()` | 与电池手册的"循环寿命"同口径 |
| **等效满循环** | 累计放出电量 / 标称容量 | — | `SOH_GetCycleMilli()`（千分之一循环） | 与 DOD 无关，适合折算寿命损耗 |

摆幅阈值 30% 比容量学习门槛 `SOH_Q_MIN_DSOC_01`（15%）**更严** —— 免得一个浅循环
既学了容量、又计了循环，把两个统计量绑在一起。

`SOH_GetCycleMilli()` 用千分之一循环为单位（`u32`），既不丢小数，也不至于几千
循环就溢出。

### 6.6 累计充放电

`SOH_GetCumDischargeMAh()` / `SOH_GetCumChargeMAh()` 两个 `u32`，各跟自己的方向
累加，静置时不动。

**落盘阈值 `SOH_COUNT_SAVE_PCT = 100`（% 标称容量）与学习结果的置脏是分开的：**

> 累计量**每帧都在变**。若每帧置脏，`BMS_NVM_Task` 的 60 s 去抖就退化成
> "每 60 s 一写"（每天 1440 次），2 槽 1 万次的介质十几天就磨穿。
> 折满一个标称容量才置一次脏 —— 掉电最多丢一个循环的计数，额外擦写量
> 约等于"每天循环数"，而且与学习结果**共用同一份载荷**，不多占一个槽。

`SOH_IsCountValid()` 区分"参数块里的计数字段有效"与"只是碰巧为 0"：ver 2 的
老数据没有这几个字段，导入后该标志为 0，读到的是 0 而不是"没充放过"。

`SOH_ResetCounters()` 只清计数，**不动学到的容量与 R0** —— 换电芯后想从零开始
计寿命，不必把学习结果一起扔掉。

### 6.7 接口一览

| 做什么 | 接口 |
|---|---|
| 取折算后的可用容量 | `SOC_GetEffectiveCapacityMAh()` |
| 取折算系数（ppm，`1000000` = 1.0） | `SOC_GetCorrPpm()` |
| 充 / 放方向 R0 任意一格 | `SOC_GetR0DirAt(dir, idx)` / `SOC_SetR0DirAt(dir, idx, mohm)` |
| 充电方向便利接口 | `SOC_GetR0ChgAt(idx)` / `SOC_SetR0ChgAt(idx, mohm)` |
| 半循环数 / 等效满循环（千分之一） | `SOH_GetHalfCycleCount()` / `SOH_GetCycleMilli()` |
| 累计放出 / 充入 | `SOH_GetCumDischargeMAh()` / `SOH_GetCumChargeMAh()` |
| 计数字段是否有效 | `SOH_IsCountValid()` |
| 清零计数（不动学习值） | `SOH_ResetCounters()` |
| 充电方向 SOH_R / R0 网格均值 | `SOH_GetResistancePercentChg()` / `SOH_GetR0ChgAvgMOhm()` |

`dir`：`0` = 放电，`1` = 充电（`SOC_R0_DIR_DIS` / `SOC_R0_DIR_CHG`）。

这些量都能通过在线调参读到：`0x24` 读计数与累计充放电、`0x25` 清计数、
`0x26` / `0x27` 读写充电方向 R0 全表、`0x28` 读折算系数（见 §8.3）。

### 6.8 恒等性与边界

| 项 | 说明 |
|---|---|
| **默认行为** | `PCT = {100,100,100}`、`k = 1.00f` ⇒ `K ≡ 1`，**逐位等同引入前**（`sim_learn.py` 第 [1] 节断言） |
| 温度表顺序 | `SOC_CAP_TEMP_PCT` 的顺序 = `BMS_CAL_TEMP_DC`。**中间那个点必须是 100**（参考温度） |
| 温度表覆盖 | 只在列出的温度点之间线性插值，端点平延不外推。默认 5~45 °C，更低温度误差最大 |
| 倍率合法区间 | `k ∈ (1.0, 1.3)`。`k < 1` 意味着"电流越大容量越多"（无物理依据）；`k > 1.3` 把 2C 压掉 25% 以上，已不是倍率效应 |
| 拟合来源 | `脚本/test/fit_temp_rate.py`，用两条以上不同倍率的放电曲线拟合 |
| 计数范围 | 累计量 mAh（`u32`，到 42.9 亿）；半循环 `u16`（到 65535 次） |
| 落盘丢失窗口 | 掉电最多丢"未满一个标称容量"的计数；学习结果不受影响 |
| 换算恒等 | `K = 1` 时 `s_corr_q16 == SOC_Q16`，两级 `65536` 相消，恰好是改造前累加器的固定倍数，换算结果逐位相同 |

## 7. 掉电保持（可选，默认关闭）

不加 `bms_nvm.*` 时学习结果全在 RAM，掉电回 100%。打开只要三步：

| 步 | 做什么 |
|---|---|
| 1 | `bms_config.h` 的 `[8]` 组里把 `BMS_USE_NVM` 改成 `1` |
| 2 | 从 `移植示例/` 挑一个 `port_nvm_*.c` 加进工程 |
| 3 | `main` 里加两行（见 §7.3） |

**算法库侧一行都不用改。** 关着的时候 `bms_nvm.c` 编译出来是 **0 字节**
（实测 `text=0 data=0 bss=0`），RAM 也是一个字节不占。

### 7.1 介质怎么选 —— 有外部就用外部

| 介质 | 写粒度 | 要擦除吗 | 寿命 | 占程序空间 |
|---|---|---|---|---|
| **外部 EEPROM (I2C)** | 1 B | 不要 | 10 万次/字节 | 0 |
| **外部 FRAM (I2C/SPI)** | 1 B | 不要 | 几乎无限 | 0 |
| STM32 VBAT 备份寄存器 | 4 B | 不要 | 无限 | 0 |
| 内部 Flash 页 / 扇区 | 2~8 B | 整页/整扇区 | 1 万次/页 | 一页 ~ 一扇区 |

1. **板上有 I2C EEPROM / FRAM → 直接用它**（`port_nvm_i2c_eeprom.c`）。
   字节可覆写、不需要擦除，寿命比内部 Flash 高一个数量级，还完全不占程序空间。
2. **只有内部 Flash** → 用末尾页/扇区，并尽量多给几个槽（见 §7.5）：
   - STM32F1 / G0 / L4 / WB / CH32X035：页 256 B ~ 4 KB，给 2~4 槽只吃 0.5~16 KB，合适。
   - **STM32F4 / F7 / H7：最小扇区 16 KB 起，存 132 字节要报废一整个扇区**（利用率 0.8%）。
     这类平台建议加一颗外部 EEPROM，而不是占用内部扇区。

### 7.2 移植层要实现的 3 个函数

| 函数 | 职责 | 返回值 |
|---|---|---|
| `BMS_NVM_SlotCount()` | 有几个独立擦除单元可用 | 槽数（≥1） |
| `BMS_NVM_SlotRead(slot, buf, len)` | 读一个槽 | 1 = 成功 |
| `BMS_NVM_SlotWrite(slot, buf, len)` | 擦除 + 写入一个槽 | 1 = 成功 |

「槽 = 一个独立擦除单元」（Flash 页 / 扇区，或 EEPROM 里的一段）。
**同一擦除单元不能拆成两个槽**，否则擦一个会连带毁掉另一个。

| 平台 | 擦除 | 写粒度 | 需要 RAM 缓冲吗 |
|---|---|---|---|
| STM32F1 | 整页 1~2 KB | 半字（2 B） | 不需要（擦写例程须在 RAM） |
| STM32F4 | 整扇区 16~128 KB | 字节/字/双字 | 不需要（扇区地址不连续，需查表） |
| STM32G0/L4 | 整页 2 KB | **双字（8 B）** | 不需要（8 字节对齐） |
| CH32X035 | 整页 256 B | 4 B | **需要 256 B**（ROM 写接口要求长度是整页） |
| 外部 EEPROM | 不需要 | 1 B | 不需要（写周期页边界不能跨） |

> **「不需要 RAM 缓冲」是怎么来的**：Flash 擦除后整页都是 `0xFF`，而我们只写前面
> 那 132 字节 —— 后面没数据的地方本来就是 `0xFF`，不用写。所以 STM32 系只需逐字
> 写 132 字节即可。只有"写接口强制整页长度"这一类平台（如 CH32X035 的 ROM API），才必须备一份 256 B 缓冲。

### 7.3 接入代码

```c
#include "bms_algo.h"

BMS_CAL_Init();          /* 1. 刷出活跃表 */
SOH_Init();              /* 2. 快照 R0 标定基线 + 清学习状态 */
BMS_NVM_Init();          /* 3. 从介质读回并覆盖 —— 必须在 SOH_Init() 之后 */

while (1)
{
    /* ... 周期分支: BMS_CAL_Update / SOC_AhUpdate / SOH_Update ... */

    BMS_NVM_Task();      /* 有未落盘的学习结果且距上次 >= 60s 时写一次 */
}
```

`BMS_NVM_Task()` 放在主循环的低频分支即可，**不要放进高频采样路径或中断**：
内部 Flash 上擦写是阻塞的（部分平台如 CH32X035 还要关中断），且擦写期间 CPU 可能取不到指令。

### 7.4 落盘格式（132 字节，跨平台逐字节一致）

头部 12 B + 载荷 120 B：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | magic `'BNM1'` |
| 4 | 2 | 格式版本（小端） |
| 6 | 2 | 落盘序号（小端，判新旧，环回安全比较） |
| 8 | 2 | CRC16-CCITT（小端），覆盖载荷 |
| 10 | 2 | 载荷长度 |
| 12 | 120 | 容量 Q · R0 表（充 / 放双向）· 标定基线 · 样本数 · 标志 ·
累计充放电 · 半循环 · 卡尔曼 P |

**为什么不用 `memcpy(结构体)`**：结构体的 padding 与字段偏移随编译器、目标位宽、
字节序变化（16 位 MCU 的 `u32` 对齐可能是 2，大端 MCU 整串反过来）。所以落盘用
**逐字段写死的偏移 + 小端**，任何平台写出来的 132 字节完全相同。CRC 也是定点的。

> 载荷长度 120 B 里，**前 68 B 与 ver 2 逐字节相同**（老工具只读前 68 B 也完全可用），
> 第 68 B 起是 ver 3 追加的充电方向 R0 与累计充放电量。字段级偏移表见
> `bms_nvm.h` 文件头 —— 那里是唯一权威，本文只写跨平台的形状。

PC 端解析：

```python
import struct
magic, ver, seq, crc, ln = struct.unpack('<IHHHH', blob[:12])
d = struct.unpack('<I 11H 11H 11B B B B h f', blob[12:80])   # 前 68 B（ver 2 起可用）
x = struct.unpack('<11H 11B B B x I I H H I', blob[80:132])  # ver 3 追加 52 B
print('Q=%d mAh  SOH_Q=%.2f%%' % (d[0], d[0] / 3350 * 100))
print('累计充 %d / 放 %d mAh，半循环 %d 次' % (x[24], x[25], x[26]))
```

> ⚠ 早期示例代码里 `62..63` 写的是 `2x`（当成对齐填充跳过）。ver 1 → 2 之后那里
> 是**有符号电芯温度**，必须解成 `h` 并把 `>> 8` 才是 °C —— 继续用 `2x` 只会静默
> 丢掉温度，不会报错。PC 侧权威实现在 `脚本/bms_tune_proto.soh_blob_decode()`，
> 它同时接受 ver 2 与 ver 3 的块。

读回时的容错：头里 magic / 版本 / 长度 / CRC 任何一项不符就判该槽无效，继续看
别的槽；全部无效才回退标称值。所以「擦到一半断电」最多丢最新那一槽，
**绝不会读进半截垃圾**。

### 7.5 寿命是怎么保下来的

内部 Flash 只有 1 万次/页，靠三道措施叠加：

| 措施 | 位置 | 效果 |
|---|---|---|
| **多槽轮转** | `bms_nvm.c` 每次写到下一个槽 | 寿命 × 槽数 |
| **内容未变就不写** | `BMS_NVM_SKIP_IDENTICAL` | 省掉「置脏但数据没变」的擦写 |
| **落盘去抖 60s** | `BMS_NVM_DEBOUNCE_MS` | 把一轮放电里的多次学习合并成一次 |

算一笔账（按每天学习 10 次）：

| 配置 | 擦写次数 | 寿命 |
|---|---|---|
| 1 槽 | 1 万 | 2.7 年 |
| 2 槽 | 2 万 | 5.5 年 |
| 4 槽 | 4 万 | 11 年 |
| 去抖改 300s + 2 槽 | 2 万（每天 2 次） | 27 年 |

外部 EEPROM 10 万次/字节 + 4 槽轮转 → 100 年以上；FRAM 基本不用考虑这个问题。

### 7.6 移植时的坑

| # | 坑 | 后果 |
|---|---|---|
| 1 | 链接脚本没把槽所在的页/扇区让出来 | 链接器把代码放进去，一擦除程序就没了 |
| 2 | 两个槽落在同一个擦除单元里 | 擦一个连带毁掉另一个 |
| 3 | CH32X035 写地址传 `0x0000F600` | ROM API 只认 `0x0800F600`，传错直接报范围错误 |
| 4 | 忘了「写前必须擦」（Flash 只能 1→0） | 旧值与新值按位与，数据错乱 |
| 5 | EEPROM 一次写跨过写周期页边界 | 地址回卷，覆盖本页开头 |
| 6 | 把 `BMS_NVM_Task()` 放进中断 | 阻塞擦写拖住中断 / 取指 stall |
| 7 | `BMS_NVM_Init()` 放在 `SOH_Init()` 之前 | 读回的值立刻被清掉 |
| 8 | 改了 `soh_param_t` 字段却没改 `BMS_NVM_VER` | 老固件仍会认新数据（版本检查失效） |

## 8. 在线调参（可选，默认关闭）

标定表、容量、R0 这些参数原先只能改 `bms_config.h` 再重新烧录。做实验时一天烧
十几次，不同电芯的 OCV 表也没法现场切换。`bms_tune` 把它们做成**运行时可读写**。

**完整协议规范见 `在线调参协议.md`** —— 帧格式、CRC 自检向量、34 条命令的逐字节
payload 布局、示例帧、上位机 / 下位机实现指南、排错清单。本节只是概览。

**接线与验收见 `移植与对齐指南.md`** —— 要写哪 11 个函数、三个平台的参考实现、
症状对照表、与上位机对齐的五步验收。

### 8.1 打开三步

```c
static ring_t g_rx;                              /* 你自己的接收环形缓冲 */

void UARTx_IRQHandler(void)                      /* 中断里只塞字节，不要解析 */
{
    if (RXNE) ring_put(&g_rx, USART_ReceiveData());
}

int main(void)
{
    BMS_TUNE_SetTx(uart_putc);                   /* 1. 注册"发一个字节" */
    for (;;)
    {
        while (ring_avail(&g_rx))
            BMS_TUNE_Feed(ring_get(&g_rx));      /* 2. 主循环里解析 + 执行 */
    }
}
```

3. `bms_config.h` 的 `[9]` 组把 `BMS_USE_TUNE` 改成 `1`。

**中断里绝不能调 `BMS_TUNE_Feed()`**：主循环的 `SOC_AhUpdate()` 正在读标定表，
中断里改表会读到"一半新一半旧"。`BMS_NVM_Save()` 同理不能进中断（擦页要关中断 10~20 ms）。

### 8.2 帧格式

```
AA 55 | LEN(u16 小端) | CMD | PAYLOAD | CRC16(u16 小端)
帧总长 = 7 + LEN        应答 = CMD|0x80，所有应答 payload[0] 都是 rc
```

CRC16-CCITT（poly `0x1021`，init `0xFFFF`，不取反）覆盖 `LEN + CMD + PAYLOAD`，
**不含 `AA 55`**，与落盘用同一套参数。自检向量：`crc16("123456789") == 0x29B1`。

`rc`：`0` 成功 / `1` 参数越界 / `2` 长度不符 / `3` 未编译进库。

### 8.3 命令一览

| 段 | 命令 | 条数 |
|---|---|---|
| `0x0_` | PING / INFO / 标定表单点与整包读写 / 恢复出厂 / 温度点读写 / 读活跃表 | 11 |
| `0x1_` | R0 活跃值读写（单点 + 全表）、容量读写、**SOC 运行态读写、EKF 8 参数整组读写、EKF 复位** | 11 |
| `0x2_` | SOH 参数块读写 / SOH 摘要 / 清学习值、**读计数与累计充放电、清计数、充电方向 R0 全表读写、读温度 / 倍率折算系数** | 9 |
| `0x3_` | 立即落盘 / 读落盘状态 | 2 |
| `0x4_` | 读实时量（SOC / SOH / Q / R0 / 温度） | 1 |
| | | **34** |

完整 34 条的 payload 布局见 `在线调参协议.md` §6。

### 8.4 标定表与 EKF 参数不落盘 —— 有意的决定

标定表（264 B）**不进 `bms_nvm`**：下位机改完表掉电就回出厂值，上位机是权威源，
上电后由它重新下发。理由：

- 落盘要 `264 + 12 = 276 B`，**超过部分平台（如 CH32X035）的单个 256 B 页**，得改成多块 / 多区域，
  `bms_nvm` 的接口（"槽 = 一个独立擦除单元"）要跟着扩；
- 标定表改动频率极低（标定一次管几个月），为它耗 Flash 寿命不划算；
- 上位机本来就要存原始标定数据，让它当权威源不会丢东西。

**EKF 的 8 个参数同样不落盘**，理由比标定表更直接：它们是"调参中间态"，
`脚本/test/kalman_tune.py` 在 PC 上扫完参数网格、验证过效果才会下发，
固件侧保住上一次的临时值反而会让人搞不清"现在跑的是哪一组"。放在
`bms_config.h` 里当出厂默认值（也是 `0x1A` 复位后的回退值）就够了。

代价：MCU 脱机不能保持标定表与 EKF 参数。真需要时扩展 `bms_nvm` 加第二存储区即可，
协议层不用动。

### 8.5 安全须知

**本模块不做任何鉴权。** 谁能往 `BMS_TUNE_Feed()` 里喂字节，谁就能改标定表、
改容量、**强制改 SOC、改 EKF 参数**、清 SOH 学习结果。改错不会让固件崩溃
（所有越界都被挡住），**但会让 SOC 算错**。

是否开放由工程侧决定（上电后 N 秒内允许 / 握手序列 / 物理按键）。
**量产固件建议默认关闭 `BMS_USE_TUNE`**，只在标定工装 / 开发版本打开。

## 9. 资源占用

实测（RISC-V GCC，`-Os -march=rv32imacxw`，`size` 口径 —— 未做 `--gc-sections`，
链接后会更小）：

| 项 | 值 | 说明 |
|---|---|---|
| Flash（核心） | **12.6 KB** | `soc.o` 6000 B + `soh.o` 6852 B + `bms_port.o` 8 B（含各自 `.rodata`） |
| RAM（核心） | **375 B** | `.data` 40 B（EKF 8 个参数 + 容量）+ `.bss` 335 B（SOH / 积分 / 极化 / 双向 R0 / 累计量），无缓冲区 |
| Flash（+掉电保持） | **+2320 B** | `bms_nvm.o`；`BMS_USE_NVM=0` 时目标文件 **0 字节** |
| RAM（+掉电保持） | **+266 B** | 读写缓冲 132 B + 影子缓冲 120 B + 状态 13 B + `s_dirty` 1 B |
| Flash（+多温度标定） | **+2160 B** | `bms_cal.o`（自带级数近似，默认不依赖 libm） |
| RAM（+多温度标定） | **+356 B** | 基准表工作副本 264 B + 活跃表 88 B + 温度/标志 4 B |
| Flash（+在线调参） | **+4728 B** | `bms_tune.o`（34 条命令）；`BMS_USE_TUNE=0` 时目标文件 **0 字节** |
| RAM（+在线调参） | **+291 B** | 接收缓冲 275 B（应答复用同一块）+ 状态 16 B |

> 上表是各目标文件之和。**真实工程链接后的实测增量比它小** —— 以早先新增
> SOC / EKF 5 条命令那一轮为例：对象文件合计 `+968 B`（`soc.o`）+ `+486 B`
> （`bms_tune.o`）`= +1454 B`，但 `--gc-sections` 链接后整个镜像只涨了
> **`text` +1040 B、`.data` +32 B、`.bss` ±0**（`text 32748 → 33788`）。
> 那 32 B `.data` 就是 EKF 的 8 个参数从编译期宏改成运行期变量
> （`s_kf_q_soc` … `s_kf_p_min`）。
>
> 经验值：**对象文件增量里大约三成会被 `--gc-sections` 吃掉**（只在关闭分支里
> 用到的常量表、相互调用的小函数都留不下来）。拿对象文件之和对 RAM/Flash 做
> 预算时按 0.7 折算，宁可留余量。

单次调用的编译产物规模：

| 函数 | `.text` | 约合指令数 |
|---|---|---|
| `SOH_Update` | 3740 B | 约 935 条（整数为主；含双向 R0 / 摆幅 / 累计量） |
| `SOC_AhUpdate` | 2984 B | 约 746 条（含安时积分 + 温度/倍率折算 + EKF） |
| `SOH_Init` | 436 B | 约 109 条 |
| `SOC_EkfSetParam` | 280 B | 约 70 条 |
| 其余查询函数 | 每个 8~280 B | 主要是查表与钳位 |

> `SOC_AhUpdate` 从约 500 条涨到 746 条，涨的几乎全在**温度 / 倍率折算**上
> （两级 `float` 乘除 + 两个插值查表）。折算**没有独立的编译开关** —— 关掉它的
> 办法就是把占位值填回去：`SOC_CAP_TEMP_PCT = {100,100,100}`、`SOC_PEUKERT_K = 1.00f`。
> 此时 `f_T ≡ f_I ≡ 1`，折算走恒等路径，结果与引入前**逐位相同**（见 §6.8），
> 代价只剩那点乘除指令。

> 精确耗时取决于平台（有无 FPU、libm 实现）。无 FPU 平台上 EKF 里最贵的是 `expf()`；
> 若它成为负担，把 `BMS_USE_LIBM_EXPF` 设 0 换库内近似（范围缩减 + 6 阶泰勒，
> 5 次乘加，相对误差 < 8e-4）。

## 10. 已知边界

- **掉电保持默认关闭**。`BMS_USE_NVM = 0`（默认）时学习结果全在 RAM，掉电回 100%。
- **标定表随附数据只有 25 °C 是实测的**，5 / 45 °C 是 25 °C 的占位副本；
  OCV 表的 0% 与 100% 两点也无实测（分别为回弹典型值与外推值）。换电芯必须重标。
- **SOH 的容量学习需要较长的静置（600 s）与足够的 SOC 跨度（15%）/ 电量（200 mAh）**。
  短循环、浅充浅放场景学不到容量 —— 这是判据本身的性质，不是 bug。
- **R0 学习只在 15~35 °C 取样本**。超出温度窗口时 R0 表不更新（SOH_R 保持上次值）。
- **精度天花板是 OCV 表**：滤波器只能把数字做稳、不能做准。
- **在线下发的 EKF 参数不落盘**，掉电回 `bms_config.h` 的出厂值（见 §8.4）。
- **在线调参不鉴权**，量产固件建议关闭。
- **温度 / 倍率修正默认是关的**（占位值 `100/100/100` 与 `k = 1.00`）。不标定就
  没有修正效果，低温与大倍率下 SOC 依然偏高 —— 这是"还不知道系数"，不是
  "算法不支持"（见 §6.8）。
- **充电方向的 R0 样本天然比放电方向少**（充电段一般更短、更少）。刚建表时
  `SOH_GetResistancePercentChg()` 会长时间停在 100%，属正常，不是坏表。
- **累计充放电在"未满一个标称容量"时不落盘**，掉电最多丢一个循环的计数；
  学习结果不受影响（见 §6.6）。
- **温度修正表只覆盖 `BMS_CAL_TEMP_DC` 列出的温度点**（默认 5~45 °C）。超出范围
  靠端点平延，而低温那一段恰恰是误差最大的（−20 °C 可用容量可低到 60~70%）。

> 温度落在最后一个区间时区间查找失败，权重按第一个区间的跨度算，
> 变成拿 5→25 °C 的斜率往外推（R0 差 36%）。三个温度点填相同占位值时
> 完全看不出来（`b − a = 0`），一填真实数据就是系统性偏差。
> **结论：这类问题指令级比对和"数值没变"都发现不了，只能靠真跑。**
>
> 同一条教训在本项目**踩了三次**，三次都是"看起来没问题"：
>
> 1. 多温度插值的区间查找（上面的 R0 差 36%）—— 三个温度点填相同占位值时
>    `b − a = 0`，偏差被完全掩盖；
> 2. `soc.c` 的等效电量累加器**少写一个 `SOC_Q16`** —— 累加器退化成 `ΣI·dt`，
>    而读取端仍按 Q16 除，纯库仑电量与 SOC 被压掉 65536 倍（恒为 0）。
>    **SOC 看上去照样在动**（EKF 在兜底），只有拿手算真值对拍才暴露；
> 3. `BMS_TUNE_PROTO_VER` 在 `bms_config.h` 与 `bms_tune.h` **各有一处 `#ifndef`
>    兜底**，而 `bms_tune.h` 自己 `#include "bms_config.h"` ⇒ 后者的值总是先定义、
>    总是胜出，前者的新版本号被静默挡掉。固件实际回的还是旧版本号，而所有
>    长度 / 语义类测试**照样全绿**。
>
> **推论：版本号、块长、字段偏移这类"元数据"必须有专人对着源码文本对拍**
> （本项目的 `脚本/test/check_consts.py` 第 [12] 节就是干这个的），不能指望
> 功能测试兜底 —— 功能测试压根不看这些字段。
