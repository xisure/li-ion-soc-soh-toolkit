## 1. 移植到底要写多少代码

**结论：11 个函数，约 400 行，一个文件就能装下。**

| 你要写的 | 文件（自己命名，示例给的是本仓库的叫法） | 函数数 | 量级 |
|---|---|---|---|
| 平台毫秒时基 | `port_<平台>.c` | **1** | 5 行 |
| 掉电保持介质 | `port_nvm_<介质>.c` | **3** | 80 ~ 150 行（可选） |
| 调参串口接线 | `uart_tune.c` / `.h` | **7** | 约 200 行（可选） |
| **合计** | | **11** | **约 400 行** |

库里 **一行 UART 代码都没有**（`算法库/*.c|h` 里搜 `UART|USART|printf|putc` 命中 0 处），
这不是省事，是刻意的：一旦 `#include` 了某家的串口头文件，这个库就只能在那一家上用。
所以同一个 `bms_tune.c` 挂在串口、USB CDC、CAN、蓝牙透传上都不用改 —— 前提是有人写那 400 行。

**代价（实测，CH32X035 / RISC-V，`-Os`）**

| 开关 | Flash | RAM |
|---|---|---|
| `BMS_USE_TUNE = 0` | **0 字节**（整个 `bms_tune.c` 不参与编译） | 0 |
| `BMS_USE_TUNE = 1` | **+3022 B** | **+291 B** |
| 其中接收环形缓冲（工程侧，`uart_tune.c`） | — | 512 B（可降到 128） |

## 2. 分层与责任边界

```
┌──────────────────────────── PC 侧 ────────────────────────────┐
│ bms_tune_proto.py / bms_gui.py    ← 拼帧 · CRC · 超时重传 · 解析 │
│                                     （协议的唯一权威实现）      │
└───────────────────────────────┬───────────────────────────────┘
                                │  USB-TTL / RS232
┌─────────────────────────── 你的板子 ───────────────────────────┐
│                                                                │
│  ┌── 串口接线层  uart_tune.c ─────────────┐  ← 【你要写】       │
│  │   RXNE 中断 ──> 环形缓冲               │                    │
│  │   主循环 UART_Tune_Task() ──> 逐字节喂 │                    │
│  │   uart_putc() <── 库的发送回调          │                    │
│  └──────────────────┬─────────────────────┘                    │
│                     │ 一次一个字节                              │
│  ┌──────────────────▼─────────────────────┐  ← 库自带【别改】   │
│  │  bms_tune.c  协议层                    │                    │
│  │   状态机 + CRC16 + 34 条命令分发        │                    │
│  │   执行时回调 bms_cal / soc / soh / nvm  │                    │
│  └──────────────────┬─────────────────────┘                    │
│                     │                                          │
│  bms_cal · soc · soh · bms_nvm        ← 库自带                 │
│  bms_port（时基 1 个函数）                                     │
│  port_nvm_*（3 个槽函数）             ← 【你要写】              │
└────────────────────────────────────────────────────────────────┘
```

**责任边界（这张表是整份文档的核心）**

| 层 | 谁负责 | 职责 | 不允许做的事 |
|---|---|---|---|
| 协议层 `bms_tune.c` | 库（**不要改**） | 字节成帧、CRC 校验、命令分发、参数越界检查 | — |
| 接线层 `uart_tune.c` | **你** | 收字节、存缓冲、喂字节、发字节、鉴权开关 | 写任何协议逻辑（一写就会和库不一致） |
| 平台时基 | **你** | 返回单调递增毫秒数 | 在中断里调库函数 |
| 掉电保持 | **你** | 一个独立擦除单元的读 / 擦 + 写 | 一个擦除单元拆成两个槽 |

**三条硬边界**（违反了不报错，只会静默算错 —— 所以必须往心里记）

1. **中断里绝不能调 `BMS_TUNE_Feed()`。** 主循环的 `SOC_AhUpdate()` 正在读标定表，
   中断里改表会读到"一半新一半旧"。中断只负责往环形缓冲塞字节。
2. **`BMS_TUNE_Feed()` 只能在主循环（非中断）上下文调用。** 推论：`BMS_NVM_Save()`
   也不能进中断（Flash 擦页要关中断 10~20 ms），而 `Feed()` 执行命令时会调它。
3. **`tx` 回调必须和主循环里其它 printf 串行**（要么都走"等发送完成再写"，要么都走
   同一个发送缓冲），否则两条路径会互相把字节插进对方输出里。详见 §9。

## 3. 移植清单（逐项打勾）

### 3.1 把文件加进工程

```
必选：bms_config.h  bms_algo.h  bms_port.h/.c  bms_cal.h/.c  soc.h/.c  soh.h/.c
可选：bms_nvm.h/.c      （要掉电保持）
可选：bms_tune.h/.c     （要在线调参）
```

应用代码只 `#include "bms_algo.h"` 一个头，其余都由它带出来。

### 3.2 打开开关（`bms_config.h`）

| 组 | 宏 | 说明 |
|---|---|---|
| `[2] 调度与时基` | `BMS_USE_TICK` | 1 = 用你的 `BMS_Port_GetTickMs()`；0 = 库内部按周期自累加 |
| `[7] 移植开关` | `BMS_USE_NVM` | 1 = 编进掉电保持 |
| `[9] 在线调参` | `BMS_USE_TUNE` | 1 = 编进调参协议层 |

**关掉的成本为零**：`BMS_USE_TUNE = 0` 时 `bms_tune.c` 编译出 0 字节，
接线层里留一组同名空函数即可（这样 `main.c` 不用加 `#if`）。

### 3.3 填空

- [ ] **时基**：实现 `uint32_t BMS_Port_GetTickMs(void)`（可调参也要它 —— 调参执行命令时要用时间）
- [ ] **掉电保持**（若 `BMS_USE_NVM=1`）：实现 `BMS_NVM_SlotCount/SlotRead/SlotWrite`
      三个函数，现成模板见 `移植示例/port_nvm_*.c`（STM32F1/F4/G0、CH32X035、I²C EEPROM）
- [ ] **调参接线**（若 `BMS_USE_TUNE=1`）：照抄 §4 或 §5 的骨架，把 3 个平台宏改写成本平台寄存器操作
- [ ] **鉴权**（可选但强烈建议看 §11）：决定"什么时候允许调参"

### 3.4 接线：初始化和主循环

```c
int main(void)
{
    BMS_CAL_Init();        /* 1. 标定表: 先刷出"当前温度的表"       */
    SOH_Init();            /* 2. 快照 R0 标定基线(作 SOH_R 分母)     */
    BMS_NVM_Init();        /* 3. 导入掉电保持 —— 必须在 SOH_Init 之后 */
    UART_Tune_Init(115200);/* 4. 调参通道 —— 必须在串口初始化之后     */

    for (;;)
    {
        UART_Tune_Task();          /* 每次循环都排空接收缓冲 */
        /* ... 你原来的周期任务: 每 200ms 调 SOC_AhUpdate / SOH_Update ... */
        /* ... 每 1s 调 BMS_NVM_Task()（擦写慢，放低频分支）... */
    }
}
```

**顺序错了不会报错，只会静默出错**

| 顺序 | 错成什么样 | 症状 |
|---|---|---|
| `BMS_CAL_Init()` 在 `SOH_Init()` 之后 | 基线取到错误的表 | SOH_R 偏 |
| `BMS_NVM_Init()` 在 `SOH_Init()` 之前 | 基线被"学过的值"覆盖 | **SOH 恒 100%** |
| `UART_Tune_Init()` 在串口初始化之前 | RX 引脚/波特率被后来的初始化冲掉 | 收不到字节 |
| `UART_Tune_Task()` 挂在 200ms 分支上 | 主循环被长任务挡住时缓冲溢出 | 长帧丢字节 |

`UART_Tune_Task()` 必须是**每次循环都调**（或者放在一个明显快于 200ms 的循环里），
不是周期任务。理由：它是"请求-应答"，越早处理延迟越低；而缓冲只有 512 字节。

## 4. 参考实现 A：CH32X035（实测）

这是本仓库的实测参考实现，下面给的是**逻辑骨架**（平台细节抽成 3 个宏）。

### 4.1 骨架

```c
/* ===== uart_tune.c : 一台"字节进 / 字节出"的机器，里面没有协议 ===== */
#include "bms_algo.h"        /* BMS_TUNE_Feed / BMS_TUNE_SetTx */

#define RXBUF   512u                 /* 必须是 2 的幂（用掩码取模，不取余） */
#define RXMASK  (RXBUF - 1u)

static volatile uint8_t  s_rx[RXBUF];
static volatile uint16_t s_head = 0u;      /* 只有中断写 */
static volatile uint16_t s_tail = 0u;      /* 只有主循环写 */
static volatile uint16_t s_ovf  = 0u;      /* 缓冲满而丢掉的字节数 */
static volatile uint8_t  s_enabled = 1u;   /* 鉴权开关，见 §11 */

/* 单生产者(中断) + 单消费者(主循环) => 不需要临界区 */
static void rx_push(uint8_t b)
{
    uint16_t n = (uint16_t)((s_head + 1u) & RXMASK);
    if (n == s_tail) { s_ovf++; return; }  /* 满 -> 丢最新这个字节 */
    s_rx[s_head] = b;
    s_head = n;
}

static uint8_t rx_pop(uint8_t *b)
{
    if (s_head == s_tail) return 0u;
    *b = s_rx[s_tail];
    s_tail = (uint16_t)((s_tail + 1u) & RXMASK);
    return 1u;
}

/* ================= 平台相关：只有这 3 个宏 ================= */
/* 把下面的 UARTx / 位名换成你的平台。
 * 注意 PLAT_RX_READ() 必须真的读数据寄存器 —— 读它才是清 RXNE 的规定动作。 */
#define PLAT_RX_READY()   (USART_GetITStatus(UARTx, USART_IT_RXNE) != RESET)
#define PLAT_RX_READ()    ((uint8_t)USART_ReceiveData(UARTx))
#define PLAT_TX_WRITE(b)  do {                                   \
        while (USART_GetFlagStatus(UARTx, USART_FLAG_TC) == RESET) { } \
        USART_SendData(UARTx, (uint16_t)(b));                     \
    } while (0)

static void uart_putc(uint8_t b) { PLAT_TX_WRITE(b); }

/* ================= 中断主体：越短越好 ================= */
void UART_Tune_IsrHandler(void)
{
    /* 顺序不能反：先查标志，后读数据（这也是清 ORE 溢出标志的规定动作） */
    if (PLAT_RX_READY()) rx_push(PLAT_RX_READ());
    /* 有 ORE/溢出标志的 MCU：在这里顺手清一下，只计数不处理 —— 帧层靠 AA 55 自恢复 */
}

void UART_Tune_Task(void)      /* 主循环每次循环调一次 */
{
    uint8_t b;
    while (rx_pop(&b))
    {
        if (s_enabled) BMS_TUNE_Feed(b);
        /* 禁用时也要把字节取走丢掉，否则禁用期间会溢出，
         * 而且重新启用后会解析到禁用期间的旧数据 */
    }
}

void UART_Tune_Init(uint32_t baud)
{
    /* 1. RX 引脚：模式按数据手册（多数是浮空输入） */
    /* 2. 串口：8N1 / 无校验 / 无流控，**Mode 必须是 Tx|Rx** */
    /* 3. 打开 RXNE 中断 + NVIC 使能 */
    BMS_TUNE_SetTx(uart_putc);     /* 4. 关键的一行：把发送回调交给库 */
}
```

中断薄壳（硬件上由它调用上面那个主体）：

```c
void UARTx_IRQHandler(void) __attribute__((interrupt("WCH-Interrupt-fast")));
void UARTx_IRQHandler(void) { UART_Tune_IsrHandler(); }
```

> **为什么把中断主体单独暴露出来**：带 `interrupt` 属性的函数以 `mret` 返回，
> 不能当普通函数调用。拆开之后，这个主体就是纯逻辑，能在 PC 上用 unicorn 直接调它做单测（§10）。

### 4.2 五个决定，以及为什么

| 决定 | 为什么 |
|---|---|
| **复用调试串口**（不另开一路） | 板上只引出了一个调试口；PC 一个 COM 口同时拿到遥测行和应答帧，接线少一半 |
| 中断里**只塞字节** | §2 硬边界 1。中断里改标定表 = 主循环读到"一半新一半旧" |
| 环形缓冲用 **512 B 2 的幂** | 最长请求帧 271 B（写整张标定表 7+264）；2 的幂可以用掩码代替取余（RISC-V 上除法要几步） |
| 发送用**阻塞等 TC**，不用 TXE 中断 | 见 §9。printf 也是"等 TC 再写"，两条路径都在主循环上下文 → 天然串行 |
| 主循环**每次循环**排空 | 缓冲只有 512 B，挂到 200ms 分支上会被 OLED 刷新（56.7 ms）顶到溢出 |

### 4.3 两个平台坑（CH32X035）

| 坑 | 现象 | 真相 |
|---|---|---|
| `NVIC_Init()` 静默忽略优先级 | 填了优先级但好像没生效 | 只有先调过 `NVIC_PriorityGroupConfig(NVIC_PriorityGroup_1)`，它才会把优先级写进 PFIC；本工程没调，静态变量是默认 0，那两个字段被**静默忽略**（不报错也不生效）。需要调优先级就先补那次调用 |
| `debug.c` 只配了 TX | 照抄初始化却收不到字节 | `USART_Printf_Init()` 里 `USART_Mode = Tx`，RX 数据线进不了移位寄存器。接线层必须**重配一次**串口，Mode 改成 `Tx|Rx`，再补 RX 引脚 |

实测结果（仿真真跑目标码，见 §10）：`UART_Tune_Init()` 之后
`CTLR1 = 0x202C`（RE|TE|RXNEIE|UE 都在）、`GPIOA_CFGLR[15:12] = 0x4`（PA3 浮空输入）。

## 5. 参考实现 B：STM32 + HAL

只换那 3 个宏，其余照抄 §4.1：

```c
#include "usart.h"                       /* huart2 由 CubeMX 生成 */

#define PLAT_RX_READY()   (__HAL_UART_GET_FLAG(&huart2, UART_FLAG_RXNE) != RESET)
#define PLAT_RX_READ()    ((uint8_t)(huart2.Instance->DR & 0xFFu))
#define PLAT_TX_WRITE(b)  do {                                            \
        while (__HAL_UART_GET_FLAG(&huart2, UART_FLAG_TC) == RESET) { }    \
        huart2.Instance->DR = (uint8_t)(b);                                \
    } while (0)

void USART2_IRQHandler(void)             /* CubeMX 生成的中断入口 */
{
    if (__HAL_UART_GET_FLAG(&huart2, UART_FLAG_ORE))
    {
        __HAL_UART_CLEAR_OREFLAG(&huart2);   /* 别忘了清，否则会反复进中断 */
    }
    UART_Tune_IsrHandler();
}
```

CubeMX 配置只需三项：**NVIC 里勾 USART2 global interrupt**、波特率与上位机一致、
GPIO 里 PA3 配成 `GPIO_MODE_INPUT`（或 CubeMX 自动配的 USART2_RX）。

**如果用 `HAL_UART_Receive_IT()` 收字节**：可以，但 `HAL_UART_RxCpltCallback()` 里
**只准塞环形缓冲**，不准调 `BMS_TUNE_Feed()`（§2 硬边界 1）；而且要在回调里立刻
重新挂一次 `HAL_UART_Receive_IT()`，否则只收到一个字节就停了。

> 注意：`__HAL_UART_GET_FLAG(&huart2, UART_FLAG_TC)` 与 `PLAT_TX_WRITE` 配合时，
> 如果工程里还有别的 `printf`（走 `_write()` → `HAL_UART_Transmit`），**它也是等 TC 的**，
> 所以同样是串行的。但如果有人用了 DMA 发送或 `HAL_UART_Transmit_IT()`，前提就没了 —— 见 §9。

## 6. 参考实现 C：裸机 / 无 OS

与 §4.1 完全一样，包括环形缓冲。三个宏换成自己的寄存器名：

```c
#define PLAT_RX_READY()   (UART0->SR & (1u << 5))     /* 举例：RXNE 位 */
#define PLAT_RX_READ()    ((uint8_t)(UART0->DR & 0xFFu))
#define PLAT_TX_WRITE(b)  do {                        \
        while (!(UART0->SR & (1u << 6))) { }          /* 等 TC */       \
        UART0->DR = (uint8_t)(b);                      \
    } while (0)
```

裸机上要额外确认两件事：

1. **`s_head` / `s_tail` 的原子性。** 32 位机读写 `uint16_t` 是单指令，天然原子（§4.1 的写法成立）。
   8 / 16 位机上读 `uint16_t` 会被拆成多条指令，`rx_pop()` 里的比较可能读到撕裂的值 ——
   把 `rx_pop()` 的判空包进临界区（关中断 → 判断并取值 → 开中断）。
2. **没有中断优先级的概念**时，若 RX 中断里同时还在做别的事，控制一下中断里干活的时长。

## 7. 常见移植错误与症状对照表

| 症状 | 最可能的原因 | 怎么确认 | 怎么改 |
|---|---|---|---|
| 上位机 PING 超时，板子一点声都没有 | `BMS_USE_TUNE` 还是 0 | 编译产物里根本没有 `bms_tune.o` | `bms_config.h` `[9]` 组改成 1 |
| 遥测行照常输出，但 PING 就是不回 | ① `BMS_TUNE_SetTx()` 没调（库直接丢弃应答）② RX 引脚没配 ③ 串口没使能 Rx | ① 有应答就等于串口通；② 量一下 RX 脚有没有波形 | 对照 §4.2 第 2 条与 §4.3 第 2 条 |
| 进了中断但字节全丢 | 中断里**没读数据寄存器** → RXNE 清不掉，反复进中断 | 中断计数暴涨、CPU 被占满 | 在中断里真的读一次数据寄存器 |
| 应答偶发缺字节 / 长帧必错 | 中断里调了 `BMS_TUNE_Feed()` | 看 ISR 里有没有 `Feed` | 改成"中断塞缓冲、主循环喂" |
| 一直 `rc = 2` | payload 长度不对 | 上位机会直接告诉你 rc | 对照协议 §6 每条命令的长度表 |
| 一直 `rc = 3` | 功能没编进去（`BMS_USE_NVM=0` 时的 `0x20/0x21/0x30/0x31`） | 看 `INFO` 的 `flags` bit0 | 打开 `BMS_USE_NVM`，或别发这几条 |
| 一直 `rc = 1` | 索引越界：`ti` 0~2、`tbl` 0~3、`idx` 0~10 | 用 `INFO` 问到的维度核对 | 索引从 0 开始数 |
| 全说 CRC 错 | CRC 覆盖范围搞反 | 拿 `PING` 的定值向量核对（见 §8.1） | 覆盖 `LEN+CMD+PAYLOAD`，**不含 `AA 55`** |
| 抓 TX 线看到半行文本夹在帧中间 | 发送有两条路径（printf 直写 + 另一条缓冲/中断） | 抓波形最直接 | 所有发送走同一套"等 TC 再写"，或全部走同一个发送缓冲 |
| 跑一会儿就不响应，复位又好 | 主循环被长任务挡住 → 环形缓冲溢出 | 读 `UART_Tune_GetRxOverflow()`，非 0 就是它 | 调大缓冲 / 缩短阻塞 / 把 `Task` 挪到更外层的循环 |
| 上电第一次能调，之后不行 | 鉴权逻辑（§11）把门关了 | 看 `UART_Tune_IsEnabled()` | 改策略 |
| SOH 恒 100% | `BMS_NVM_Init()` 排在 `SOH_Init()` 之前 | 看初始化顺序 | 交换（§3.4） |
| 改了 R0 / 标定表，重启就丢 | **标定表本来就不落盘**（有意的决定，协议 §6.2） | — | 用上位机导出 bin 存档，或改的是"学到的值"（那个会落盘） |
| 板子应答正常，但上位机偶尔报超时 | 上位机超时太短（板子最长应答 23.6 ms，加上 PC 调度） | 看上位机的 timeout 设置 | 默认 0.3 s 够；别调到几十毫秒 |

<a id="8"></a>
## 8. 与上位机对齐：五步验收

**"移植完了"的定义不是"编译过了"，而是下面五步都过。**

### 第 0 步：PC 侧自检（接板子之前先跑）

```
python bms_tune_proto.py
```

它检查 CRC 定值向量与 `PING` 帧逐字节一致，并列出 34 条命令。自检不过说明
**上位机（或你抄的 CRC）**有问题，跟板子无关 —— 先别急着怀疑硬件。

### 第 1 步：PING（握手）

| 方向 | 字节 |
|---|---|
| PC → 板子 | `AA 55 00 00 00 9C CC` |
| 板子 → PC | `AA 55 03 00 80 00 02 00 AA 7B` |

> 与 `在线调参协议.md` §7 示例 1 逐字节一致。
> 注意上行第 5 字节是 `80`（`CMD 0x00 | 0x80`）—— 上位机拼**请求**帧时会 `cmd & 0x7F`，
> 所以别拿请求拼帧函数去生成应答帧来对拍。

判据：收到 **10 字节**、第 5 字节是 `0x80`（`0x00 | 0x80`）、
payload 是 `00`（rc=OK）+ `02 00`（proto_ver=2）。

### 第 2 步：INFO（维度对齐）

判据：`temp_n=3`、`tbl_n=4`、`soc_n=11`、`cal_bytes=264`、
`flags` bit0 = 1（掉电保持已启用）。
**这四个数不上位机不硬编码**，界面的网格规模全靠它 —— 所以这一步不过，
后面所有批量操作都会按错误的长度拼帧。

### 第 3 步：读 → 改 → 写 → 读回（最小闭环）

```
RD_TEMP  → 记下当前温度点
RD_CAL_POINT(ti, tbl, idx) → 记下原值
WR_CAL_POINT(ti, tbl, idx, 原值 + 1)
RD_CAL_POINT(ti, tbl, idx) → 必须读到 原值 + 1
WR_CAL_POINT(ti, tbl, idx, 原值)     ← 改回去
CAL_RESTORE                           ← 更彻底：整表恢复出厂
```

判据：写进去的和读回来的一字不差；最后能恢复原值。
**这一步能同时验证"读路径 + 写路径 + 库内参数校验"三条链路。**

### 第 4 步：长帧 + 混合流

- 发 `RD_CAL_ALL`，期望应答 **272 字节**（`7 + 1 + 264`），一次收完不截断。
  这是最长的应答，也是唯一能暴露"环形缓冲太小 / 主循环太慢"的命令。
- 期间板子会照常输出 5 Hz 遥测行 —— 如果上位机把它们当成了帧数据，说明它没有
  正确地"扫 `AA 55` 跳过垃圾"（§9）。

### 第 5 步：断电重连

- 拔掉 USB 再插上，直接发 `PING`，应立刻应答（不需要任何额外的唤醒序列）。
- 如果第 1 步是通的、这一步不通：多半是鉴权逻辑把门关了（§11）。

### 通过判据汇总

| 项 | 期望 |
|---|---|
| 超时次数 | 0（连发 20 次 PING，`timeout` 计数保持 0） |
| CRC 错误次数 | 0 |
| `rc` | 全部 0（除了故意发的越界命令应该是 1 / 2 / 3） |
| 长帧 | `RD_CAL_ALL` 一次收到 272 字节 |
| 遥测 | 调参期间遥测行不丢、不串（用 `soc_record.py` 同时采集验证） |

<a id="9"></a>
## 9. 真板子上的混合流

真板子上，**同一个 COM 口里同时有两种数据**：

```
D,3845,1234,253,6800,9666,3238,62\r\n      ← 5 Hz 遥测行（你的 printf）
D,3846,1231,253,6798,9666,3238,62\r\n
AA 55 03 00 00 00 01 00 C1 F3              ← 调参应答帧
D,3847,1229,253,6796,9666,3238,62\r\n
```

它们能共存，靠的是三件事，**缺一件就会出问题**：

1. **帧头第一个字节是 `0xAA`，而 ASCII 只到 `0x7F`。**
   文本遥测行里**不可能**出现 `0xAA`，所以 PC 端"扫 `AA 55`"不会误判到文本行中间。
   （注意：`0x55` 是字符 `'U'`，是可能出现在文本里的；但孤立的 `'U'` 凑不成帧头。）
2. **所有发送者都在主循环上下文、都用"等 TC 再写"**（`printf` 走 `_write()` 也是等 TC）。
   于是 `printf` 和调参应答天然串行，不会有两边同时写数据寄存器的情形。
   - 反例：如果调参应答改用 TXE 发送中断，就会出现"主循环 printf 写到一半被发送中断插字节"。
3. **中断只往缓冲塞字节，解析全在主循环**（§2 硬边界 1）。

**什么时候这个前提会被打破**（改代码前先想清楚）：

| 改动 | 后果 | 补救 |
|---|---|---|
| 给调参应答加 DMA 发送 | 与 printf 抢数据寄存器 | 所有发送都改走同一个发送缓冲 |
| 在某处用 TXE 中断发字节 | 同上 | 同上 |
| 在中断里 `printf`（比如 ADC 中断里打印） | 与主循环 printf 抢，且中断里 `Feed` 的风险重现 | 中断里只置标志，打印挪到主循环 |
| 把遥测改成二进制格式 | 二进制里可能出现 `0xAA 0x55`，帧同步会误判 | 遥测保留文本行，或给自己加一层转义 |

**上位机侧要注意的**：解析器必须是"扫描 `AA 55` → 长度 → CRC 校验 → 不通过就
从下一个字节继续扫"，而不是"假设读到的就是帧"。CRC 在这里承担了
"排除误同步"的职责，所以它不能省。

## 10. 不上板子也能验证

板子还没打样 / 还在焊的时候，这套东西已经可以验证到"逻辑上确定没问题"的程度。
本仓库的做法（验证脚本本体不随仓库发布，这里只描述方法）：

| 层次 | 方法 | 能查出什么 |
|---|---|---|
| 协议层 | 用 RISC-V 交叉编译器把 `bms_tune.c` 编成 ELF，在指令级模拟器里真跑目标码，喂十六进制帧、抓发送回调 | 帧格式、CRC、34 条命令的长度与越界检查 |
| 文档层 | 让固件真跑一遍，把 34 条命令的下行长度 / 上行长度与 `在线调参协议.md` 的数字**逐条对拍** | 文档抄错长度（这类错误在板子上的表现是"发下去没反应"，极难定位） |
| **接线层** | 把 `uart_tune.c` + `bms_tune.c` + 芯片官方外设库一起编进模拟器，把串口寄存器映射成普通内存："收到字节"= 往数据寄存器写 + 置 RXNE 位；"发出字节"= 内存写钩子抓走。**用上位机的真实客户端模块通过一个假 transport 去驱动它** | 引脚/寄存器配置、环形缓冲、半截帧跨中断、缓冲溢出与恢复、CRC 错帧静默丢弃、禁用/启用、混合流 |
| 上位机层 | 假串口（内存 transport）跑命令表自检与解析 | 拼帧、CRC、解析、超时重传 |

接线层那一档特别值得做，因为它能在流片前就回答"接到板子上会不会不工作"。
实测覆盖的 25 项里包括：

- `UART_Tune_Init()` 真的把 RX 那一半配出来了（读回 `CTLR1` 与 GPIO 配置寄存器）
- 一帧拆成 3 段喂（半截帧跨多次中断/主循环）仍能拼出应答
- 流里混入遥测文本行，应答仍被正确解析
- CRC 错帧 → 固件不应答 → 上位机超时重传后成功
- 连灌 600 字节不取 → 溢出计数增加；排空积压后帧同步自恢复
- 禁用 → 不应答且丢弃计数增加；重新启用 → 恢复

> 最后一档（真板子）仍然必须做：模拟器里的"串口"不会有时序抖动、不会有
> 电气问题、不会有真实的 PC 驱动。§8 的五步验收就是真板子的那一关。

## 11. 移植后必须自己决定的一件事：鉴权

**`bms_tune` 不做任何鉴权。** 谁能往 `BMS_TUNE_Feed()` 里喂字节，谁就能改标定表、
改容量、清 SOH 学习结果。改错了不会让固件崩溃（越界参数都被挡住），
**但会让 SOC 算错** —— 后者更危险，因为它不报错，只是慢慢偏。

所以"什么时候允许调参"必须由工程侧决定。实现上就是接线层里那个开关：

```c
void UART_Tune_Enable(uint8_t on);

/* 或者更简单：在 Task 里判断 */
void UART_Tune_Task(void)
{
    uint8_t b;
    while (rx_pop(&b))
    {
        if (允许调参()) BMS_TUNE_Feed(b);
    }
}
```

三种典型策略：

| 策略 | 做法 | 适用 |
|---|---|---|
| **常开** | 什么都不做 | 标定工装 / 实验板 |
| 上电限时 | 上电后等一个标志位，N 秒后置 0 | 量产但保留产线调试窗口 |
| 握手序列 | 收到特定字节序列（或物理按键按下）才置 1 | 量产，防止现场误改 |

**两个容易忘的点**：

1. **关闭时要 `BMS_TUNE_Reset()`**（清掉协议层状态机里的半截帧）。
   否则"禁用期间的残留字节 + 启用后新来的字节"可能拼成一帧来源不明的命令。
   启用时也要清，防止"启用前收到的半截帧"立刻被执行。
2. **禁用时仍然要把字节取走丢掉**（`Task` 里 `rx_pop` 照常做），
   否则禁用期间缓冲会溢出，而且重新启用后会解析到禁用期间的旧数据。

量产固件建议 **直接关掉 `BMS_USE_TUNE`**（成本 0 字节），只在标定版本打开。
